# C# 脚本执行模型

CycleScript 使用同步的 C# 方法组织剧情。事件被触发时，普通 C# 逻辑立即执行，角色和引擎 API 将表现指令加入队列；运行器随后按顺序执行这些指令。

本文描述约定的实现方向。事件注册已经实现，指令队列、选项调度和脚本 API 仍需接入，具体进度见文末。

## 基本职责

| 部分 | 职责 |
| --- | --- |
| Chapter | 一个章节的脚本实例，持有角色引用和剧情变量。 |
| Event | 无参数、返回 `void` 的实例方法，执行剧情逻辑并构建一批指令。 |
| 脚本对象和 API | 提供 `Say`、`Move`、`Option` 等调用，将对应操作加入队列。 |
| 指令队列 | 保存待执行的操作，以及各操作的完成条件。 |
| 运行器 | 维护主线位置，执行队列，处理等待、选项和分支返回。 |
| 生成器 | 在编译期收集事件，生成绑定到脚本实例的委托和顺序信息。 |

生成器只负责事件注册，不改写事件方法体，也不自动把普通 C# 语句转成指令。

## 脚本示例

下面是章节内部的示意代码。`Character` 的构造方法、`Say`、`Move` 和 `engine.API` 尚待实现；`engine` 表示运行器提供给脚本的当前引擎上下文。

```csharp
private readonly Character bob = new Character("init...");
private int i = 0;

[CycleEvent]
private void Event1()
{
    bob.Say("Hi");
    bob.Move(0, -50, 2000); // x、y、持续时间（毫秒）
    engine.API.Option("Yes", Option1);
    engine.API.Option("No", Option2);
}

[CycleEvent(AutoRun = false)]
private void Option1()
{
    i++;
    bob.Say("Ok");
}

[CycleEvent(AutoRun = false)]
private void Option2()
{
    bob.Say("Ok");
}

[CycleEvent]
private void Result()
{
    if (i > 0)
    {
        bob.Say("You chose Yes.");
    }
}
```

`Option1`、`Option2` 在注册选项时作为方法引用传入，此时不执行它们。

## 加载章节

1. 创建章节实例，并连接当前引擎的脚本 API 与角色对象。
2. 取得生成器提供的配置和事件委托，不预先调用所有事件方法。
3. 初始化章节，调用 `OnLoad()`；如果初始化产生指令，先执行完这批指令。
4. 按自动事件顺序开始推进主线。

配置需要区分两份信息：

- **全部事件的注册表**：包含自动事件和 `AutoRun = false` 的分支事件。
- **自动事件的执行顺序**：只包含需要沿主线自动执行的事件。

示例中的自动顺序为 `Event1 → Result`。`Option1` 和 `Option2` 保留在注册表中，等待玩家选择触发，不占用自动执行位置。

同一文件内沿用事件声明顺序；跨 partial 文件的顺序沿用现有生成器规则，详见[生成器说明](../../../docs/source-generator.md)。

## 执行一个事件

运行器先同步调用当前事件方法，让它完成本次入队，再执行这批指令。当前事件完成后，才调用下一个自动事件的方法。

例如，`Event1()` 构建的队列为：

```text
Say("Hi") → Move(0, -50, 2000) → Choice(Yes / No)
```

每条指令定义自己的完成条件。立即操作可以当次完成；对白可以等待玩家确认；移动可以等待动画结束；选择节点等待玩家作出选择。运行器通过更新或回调检查完成状态，完成后取下一条指令。

事件方法返回只表示本次入队完成。当前指令完成、队列清空且没有未结束的选择分支后，运行器才继续自动事件顺序。等待期间，宿主仍正常更新画面和输入，不在事件方法里阻塞等待。

## 选项与分支

示例中连续的两次 `Option()` 调用共同组成一个选择节点。执行到该节点时，同时显示 Yes 和 No，暂停主线推进。

玩家选择 Yes 后：

1. 结束选项输入，触发一次 `Option1()`。
2. `i++` 立即执行，章节实例中的 `i` 变为 `1`。
3. `bob.Say("Ok")` 产生分支指令，并由运行器执行。
4. 分支指令完成后，恢复主线，调用 `Result()`。
5. `Result()` 此时读取到 `i == 1`，进入对应分支并构建自己的指令。

选择 No 时执行 `Option2()`，随后同样回到 `Result()`，此时 `i` 仍为 `0`。

分支执行复用同一个章节实例。触发分支不重新创建章节，也不把分支方法加入自动执行顺序；主线位置由运行器保留。

## 普通 C# 逻辑与指令的执行时机

赋值、`if`、循环和普通方法调用，在当前事件被触发时按 C# 的正常规则执行。表现 API 负责提交指令，表现效果在队列执行到相应指令时发生。

因此，示例中的 `i++` 无需包装成队列动作，`Result()` 中的 `if` 也可以直接写。后续事件不会提前执行，它能读取此前已触发分支更新的剧情变量。

同一事件内，若逻辑需要读取某条表现指令执行后的结果，应将后续逻辑放在完成后触发的事件中。仅把指令加入队列，不代表动画、输入或其他表现效果已经完成。

## 可见性与标识

事件是否注册由 `[CycleEvent]` 决定，`public` 和 `private` 均可。私有事件通过生成器创建的委托执行，无需公开为脚本的直接调用接口。

普通章节和事件的注册键不承诺跨重命名保持稳定，不把方法名或示例事件名当作固定契约。`Script:onload` 是约定保留的固定生命周期入口；它与普通事件的命名约定分开处理。
